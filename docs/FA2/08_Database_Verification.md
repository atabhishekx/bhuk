## 3. Data Integrity Checks

### Money in Minor Units (Paise)
- All monetary fields use `INT` with suffix `*_minor` (e.g., `base_price_minor`, `subtotal_minor`, `tax_minor`, `delivery_fee_minor`, `grand_total_minor`)
- ✅ Consistent across all pricing tables
- ✅ Tax calculated at 5% of subtotal, rounded appropriately
- ✅ Delivery fee fixed at ₹40 (4000 paise)
- ✅ Free delivery threshold logic exists in service layer

### Order Number Format
- Format: `RSTR-YYYYMMDD-XXXX` (e.g., `RSTR-20251025-0001`)
- Generated by `OrderNumberGenerator`
- ✅ Uniqueness enforced by database
- ✅ Daily sequential numbering

### State Machines

#### Order States
`PLACED` → `ACCEPTED` → `PREPARING` → `READY_FOR_PICKUP` → `PICKED_UP` → `OUT_FOR_DELIVERY` → `DELIVERED`

Terminal states: `REJECTED`, `CANCELLED`, `DELIVERY_FAILED`
- ✅ Enforced in `OrderService.ALLOWED_TRANSITIONS`
- ✅ Audit trail in `order_status_events`

#### Delivery States
`UNASSIGNED` → `OFFERED`/`ASSIGNED` → `ACCEPTED` → `PICKED_UP` → `COMPLETED`

Terminal states: `DECLINED`, `EXPIRED`, `FAILED`, `CANCELLED`
- ✅ Enforced in `DeliveryService.ALLOWED_TRANSITIONS`

### Idempotency
- `idempotency_key` unique constraint on orders table
- `idempotency_records` table stores request hashes with 24-hour expiry
- ✅ Prevents duplicate order creation

### Snapshots
- Order items store `item_name_snapshot` and `unit_price_minor` at purchase time
- Order item modifiers store `name_snapshot` and `price_delta_minor`
- ✅ Ensures historical accuracy even if menu changes
